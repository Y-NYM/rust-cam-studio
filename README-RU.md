# Rust Cam 0.4.1 — Android

Рабочая основа: Rust / egui, Camera2 / JNI, GPU-превью и видеозапись,
CPU-обработка фотографии. Пакет `cam.dazz.rust`, ARM64, Android 8+.
Числовые рецепты эффектов — инженерные приближения; совпадение с Dazz Cam
не подтверждено. Оригинальные текстуры не доказывают точность алгоритмов.

## Доработанный этап

- Раздельные панели EV, фокусного расстояния, двумерного WB и таймера.
- Меню превью, сетка, уровень, фокус по касанию.
- Двойная экспозиция двух снимков/импортов, отдельно от коллажа.
- Менеджер, Legacy, видимость и порядок камер; сохранение выбора и параметров KV88.
- Динамическая Frame-область; обрезка перед наложением плёночной рамки.
- Исправлена Inst SQ/SQC/Inst C: фотография помещается только во внутреннее
  окно карточки; прозрачная внешняя область не показывает фото. Пропорции
  бумаги сохранены, внешние прозрачные поля текстуры обрезаются. Поэтому
  итоговый JPEG с рамкой имеет пропорции карточки, а не квадратного снимка.
- EV действует в превью и JPEG один раз; импорт сохраняется как исходник,
  повторного наложения фильтра при сохранении нет.
- JPEG quality 94: временный файл → sync → rename → публикация тех же байтов
  в Pictures/Dazz Rust. При отказе публикации частная копия остаётся.
- MP4 H.264/AAC публикуется в Movies/Dazz Rust.

## Сборка и проверки

Нужны Rust с `aarch64-linux-android`, JDK 21, SDK android-35,
build-tools 36.0.0, NDK 29.0.14206865. Пути заданы в build-android.ps1.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .uild-apk.ps1
cargo test -p dazz-core -p dazzcam --lib --locked
```

Использовать существующий `signing/dazz-local.keystore`. Частный ключ не входит
в переносимый архив. При отсутствии ключа сборка прекращается: новый ключ
не даёт обновить установленное приложение. Не удалять приложение и его данные.

27.11.2026: 22 unit tests; эмулятор Android 15, ARM64 через native bridge.
Проверены обновление прежней подписью, JPEG, отмена таймера, double exposure,
панели, видимость/порядок, Legacy, KG200, relaunch, импорт, галерея и видео.
Четыре экспортированных JPEG (KV88, CCD R, Inst SQC, Original) сравнивались
с копиями в MediaStore: SHA-256 совпал. MP4 1280×720 H.264/AAC декодируется.
Итоговая запись JPEG проверена после последнего изменения сохранения.

## Ограничения

- Реальный телефон не подключён: матрица rear/front/позы/JPEG/video не подтверждена.
- Грейды, WB, blend двойной экспозиции 50/50, Frame=24/focal и параметры KV88
  приближённые. Auto WB сбрасывает программную коррекцию к нейтральной;
  Camera2 сохраняет собственный AWB. EV — программная коррекция, не ручная AE.
- Jitter пока использует chroma/scanlines; Halation — bloom. Точные операции
  оригинала, полноценные Prism/Star, RAW/3D/GIF и анимации не восстановлены.
- Четвёртая функция таймера неизвестна, поэтому не выполняет выдуманное действие.
- CPU JPEG и GPU preview/video различаются зерном, blur и sampling; равенство
  пикселей между ними не заявлено. Live preview делает readback около 10 fps;
  производительность, расход батареи и нагрев на телефоне не измерены.
- Windows desktop UI отдельно не принят; --lib tests проходят. Полный cargo test
  с desktop cdylib упирается в предел export ordinal GNU linker в debug.

Сценарии тестов, скриншоты, экспортированные фотографии и хеши находятся
в соседнем пакете результатов текущей работы.
